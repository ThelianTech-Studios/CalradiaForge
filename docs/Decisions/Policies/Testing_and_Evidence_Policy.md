# Testing and Evidence Policy

Report the exact command, project/configuration, result, and limitations for
automated verification. Separate build, test, benchmark, static, manual UI,
Steam/Bannerlord, packaged-runtime, and release evidence. Do not infer a manual
runtime result from a green test run or call an unavailable advisory/security
scan clean.

For asynchronous operations, preserve evidence of admission, cancellation,
terminal classification, cleanup, and quiescence. Real-installation benchmarks
must be explicit-consent, offline, read-only, sanitized, and tied to their
corpus/environment. Findings stay pending until owner/developer disposition.

See [Testing](../../06_Development/Engineering/Testing/README.md),
[Manual Runtime Verification](../../06_Development/Engineering/Testing/Manual_Runtime_Verification.md),
and [Benchmarking](../../06_Development/Engineering/Benchmarking/README.md).
