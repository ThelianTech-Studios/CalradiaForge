# Release Process

1. Establish the accepted source endpoint and owner-approved scope.
2. Verify project/version metadata, build, tests, packaging, and applicable
   manual/runtime scenarios.
3. Record unresolved findings and limitations; do not convert them into a clean
   release claim.
4. Update the changelog and version-specific public record only after the source
   endpoint is accepted.
5. Link evidence under [Reviews](../Reviews/README.md) rather than duplicating
   full reports in a release folder.
6. Leave commit, push, publication, and release creation to the owner unless
   explicitly authorized.
