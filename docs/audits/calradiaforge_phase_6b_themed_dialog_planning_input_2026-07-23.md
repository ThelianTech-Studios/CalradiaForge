# Phase 6.B Themed Lifecycle Dialog Planning Input

**Status:** Documentation-only planning input.

**Purpose:** Supply current-source evidence and WPF reference material for an owner-authored implementation plan.

**Authority:** This report does not authorize implementation. Current source, accepted architecture, the Phase 6.B locked decisions, and the owner's future instruction prompt remain authoritative.

## Owner-Confirmed Direction

The current shutdown, restart, delayed-shutdown, and fatal-error prompts should not remain a `Window` assembled entirely in C#.

The intended presentation pattern is:

1. a dedicated WPF window `.xaml` file for structure and control declarations,
2. a small `.xaml.cs` code-behind for transient dialog behavior and results,
3. a dedicated resource dictionary for window-specific styles and templates,
4. shared theme tokens and genuinely shared title-bar resources referenced through `StaticResource`,
5. fresh dialog-window instances created through the existing dialog service.

This follows the existing Language Selection and EULA window approach. It also keeps visual definitions out of lifecycle/service code and prevents the new window XAML from becoming cluttered with full control templates.

## Confirmed Current Problem

The active Visual Studio 2026 Debug instance was inspected on 2026-07-23. The launcher used the expected dark red CalradiaForge theme, but the shutdown prompt displayed:

- standard Windows title-bar chrome,
- a white window background,
- hard-coded black message text,
- default gray buttons,
- no CalradiaForge-specific window or button template.

The current implementation is:

- `source/CalradiaForge.UI/Dialogs/ApplicationDialogService.cs`
  - creates a new `ConfirmationDialogWindow` for shutdown, restart, delayed shutdown, and fatal-error presentation;
- `source/CalradiaForge.UI/Dialogs/ConfirmationDialogWindow.cs`
  - derives directly from `Window`;
  - constructs its `Grid`, `TextBlock`, `StackPanel`, and `Button` objects in C#;
  - explicitly sets `Foreground = Brushes.Black`;
  - assigns no CalradiaForge window, message, or button style;
- `source/CalradiaForge.UI/Dialogs/DialogContracts.cs`
  - defines the narrow application-level dialog contract;
- `source/CalradiaForge.UI/Composition/ServiceCollectionExtensions.cs`
  - registers the dialog service as a singleton.

`DialogOwner.Assign` correctly assigns `Application.Current.MainWindow` as the owner when available. Owner assignment supplies the parent relationship and enables owner-relative centering; `ShowDialog()` supplies modality. Ownership does not transfer the main window's visual styles.

## Existing Close And Restart Flow

### Normal close

1. `MainWindow.CloseButton_Click` calls `Close()`.
2. WPF raises `MainWindow.Closing`.
3. `MainWindow_Closing` cancels direct closure and calls `IApplicationLifetime.RequestShutdownAsync`.
4. `App.RequestShutdownAsync` supplies `IApplicationDialogService.ConfirmShutdown` as the pre-commit confirmation.
5. Declining returns without committing shutdown; `MainWindow` stays open.
6. Accepting starts the app-owned shutdown pipeline.
7. The pipeline stops new work, requests cancellation, waits for quiescence, stops notification delivery, persists authorized state, disposes the provider/logger, marks `MainWindow` prepared, and calls `Application.Shutdown()`.

This routing is intentional. It ensures the custom close button, Alt+F4, and other ordinary WPF close requests use the same lifecycle policy.

### DebugMode restart

1. `SettingsPage.DebugMode_Toggled` persists the new value immediately.
2. It calls `IApplicationLifetime.RequestRestartAsync`.
3. `App.RequestRestartAsync` supplies `IApplicationDialogService.ConfirmRestart` as the pre-commit confirmation.
4. Declining keeps the persisted next-process setting and leaves the current logger unchanged.
5. Accepting runs the same controlled shutdown pipeline, disposes the provider/logger, launches the replacement process, and shuts down the original process.

The shutdown and restart prompts therefore share one presentation problem: both are generated by the same code-only `ConfirmationDialogWindow`.

## Behavior And Architecture That A Replacement Must Preserve

The future implementation plan should preserve these contracts:

- Keep `IApplicationDialogService` narrow and UI-owned.
- Keep the dialog service registered as a singleton.
- Create a fresh WPF dialog window for every invocation.
- Do not register the dialog window itself as a singleton.
- Keep lifecycle decisions and shutdown/restart orchestration in `App` and the lifecycle coordinators, not in the window.
- Keep the window responsible only for presentation, transient choice state, title-bar interaction, and `DialogResult`.
- Preserve `ShowDialog()` modality and owner assignment.
- Preserve current result mappings:
  - shutdown primary choice → commit shutdown;
  - shutdown secondary/native close → cancel;
  - restart primary choice → commit restart;
  - restart secondary/native close → do not restart;
  - delayed-shutdown primary choice → continue waiting;
  - delayed-shutdown secondary choice → exit anyway;
  - fatal-error prompt → one close action.
- Preserve Core/UI layering; all XAML and WPF behavior stays in `CalradiaForge.UI`.
- Do not move shutdown, restart, persistence, logger disposal, or process-launch logic into code-behind.
- Do not introduce a service locator or expose the root provider.

### Edge cases the plan must address explicitly

- The delayed-shutdown window's native close currently resolves to `ExitAnyway`; the replacement must make that semantic choice explicit rather than inherit it accidentally.
- A fatal startup occurring before the provider/dialog service exists currently uses `MessageBox.Show`; replacing that bootstrap fallback is a separate decision and must not be assumed.
- Noninteractive fatal and operating-system shutdown paths bypass normal confirmation.
- The app-domain fatal path and dispatcher fatal path do not have identical UI opportunities.
- `WindowStyle="None"` requires custom drag and close behavior.
- Enter, Escape, `IsDefault`, `IsCancel`, initial focus, focus visuals, and Alt+F4 behavior must be defined for each dialog mode.
- The dialog must remain usable if no owner window is loaded.

## Presentation Responsibility Split

### Window XAML

The `.xaml` file should contain:

- the `Window` declaration and structural layout;
- custom title-bar structure;
- icon, title binding/content, drag surface, and close control;
- message/content structure;
- primary and optional secondary buttons;
- named controls and event hookups;
- references to keyed component styles.

It should avoid embedding full brushes, control templates, hover states, typography systems, and repeated theme values.

### Code-behind

The `.xaml.cs` file should remain small and contain:

- `InitializeComponent()`;
- constructor input assignment for title, message, button labels, and dialog mode;
- transient selected-result state;
- title-bar drag behavior;
- primary, secondary, and custom-close handlers;
- explicit `DialogResult` behavior.

It should not construct the visual tree, own application lifecycle policy, resolve services, dispose the provider/logger, persist application state, or launch processes.

### Dedicated resource dictionary

The resource dictionary should own:

- window background or gradient;
- surface and border styling;
- title-bar background, dimensions, and typography;
- message typography;
- primary and secondary button templates;
- hover, pressed, disabled, focus, and default-button states;
- component-specific sizing, spacing, corner radii, and cursor behavior.

It should consume existing theme tokens such as `TB.Bg.*`, `TB.Sfc.*`, `TB.Txt.*`, `TB.Acc.*`, `Font.Primary`, and `Font.Secondary`. It may consume genuinely shared title-bar resources, but it should not borrow styles whose semantics belong to unrelated pages.

## Important Differences From The Language Reference

The Language Selection window is the correct structural reference, but it should not be copied blindly:

- It uses `CenterScreen`; an owned lifecycle dialog should normally use `CenterOwner`.
- Its background gradient is still declared inline in its XAML. The requested lifecycle-dialog separation is stricter, so the new window background should be moved into its dedicated resource dictionary.
- It borrows `ModsPageComboBox`, which is appropriate for its current implementation but not a pattern for lifecycle-dialog buttons or surfaces.
- It does not define the two-choice keyboard semantics required by confirmations.
- Its visible text is hard-coded; lifecycle localization remains a planning decision.

```csharp
namespace CalradiaForge.UI.Views;

using System;
using System.Collections.Generic;
using System.Linq;
using System.Windows;
using System.Windows.Controls;
using System.Windows.Input;

using CalradiaForge.Core.Models;

/// <summary>
/// Modal language selection window shown on first launch before EULA.
/// </summary>
public partial class LanguageSelectWindow : Window {
	/// <summary>
	/// Gets the selected language code when the dialog is accepted.
	/// </summary>
	public string SelectedLanguageCode { get; private set; } = "en-US";

	/// <summary>
	/// Initializes the language selection window.
	/// </summary>
	public LanguageSelectWindow(IReadOnlyList<LanguageOption> availableLanguages, string currentLanguageCode) {
		InitializeComponent();

		List<LanguageOption> languageOptions = (availableLanguages ?? [])
			.Where(l => !string.IsNullOrWhiteSpace(l.Code))
			.ToList();

		if (languageOptions.Count == 0) {
			languageOptions.Add(new LanguageOption {
				Code = "en-US",
				DisplayName = "English (United States)"
			});
		}

		LanguageComboBox.ItemsSource = languageOptions;

		int selectedIndex = languageOptions
			.Select((lang, i) => new { lang, i })
			.FirstOrDefault(x => string.Equals(x.lang.Code, currentLanguageCode, StringComparison.OrdinalIgnoreCase))?.i ?? 0;

		LanguageComboBox.SelectedIndex = selectedIndex;
		if (LanguageComboBox.SelectedItem is LanguageOption selected) {
			SelectedLanguageCode = selected.Code;
		}
	}

	/// <summary>
	/// Enables dragging the window by the title bar.
	/// </summary>
	private void TitleBar_MouseLeftButtonDown(object sender, MouseButtonEventArgs e) {
		try {
			DragMove();
		} catch (InvalidOperationException) {
			// Mouse was released outside the window bounds during dragging.
		}
	}

	/// <summary>
	/// Closes the window without explicit confirmation.
	/// </summary>
	private void CloseButton_Click(object sender, RoutedEventArgs e) {
		DialogResult = false;
		Close();
	}

	/// <summary>
	/// Updates in-memory selected language state when the user changes selection.
	/// </summary>
	private void LanguageComboBox_SelectionChanged(object sender, SelectionChangedEventArgs e) {
		if (LanguageComboBox.SelectedItem is LanguageOption selected) {
			SelectedLanguageCode = selected.Code;
		}
	}

	/// <summary>
	/// Confirms selected language and closes the window.
	/// </summary>
	private void ContinueButton_Click(object sender, RoutedEventArgs e) {
		if (LanguageComboBox.SelectedItem is LanguageOption selected) {
			SelectedLanguageCode = selected.Code;
		}
		DialogResult = true;
		Close();
	}
}
```
